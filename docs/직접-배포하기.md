# 직접 배포하기 (다른 서버·다른 Firebase 프로젝트)

이 앱은 **화면(정적 파일)**과 **자료(Firebase: 익명·Google 로그인 + Firestore)**로 나뉩니다. 화면은 어떤 웹 서버에 올려도 되지만, 자료는 항상 Firebase 프로젝트에 저장됩니다. 그래서 먼저 둘 중 하나를 정해야 합니다.

| | A. 같은 자료를 다른 주소로 | B. 우리 학교와 별개인 새 자료 |
| --- | --- | --- |
| 자료 | 아산초 운영 자료(`asan-curriculum-link-2026`)를 **함께** 읽고 씀 | 새 Firebase 프로젝트, 처음부터 따로 |
| 바꿀 것 | 없음 (빌드해서 올리기만) | 설정 파일 5곳 + Firebase 콘솔 설정 |
| 주의 | 그 주소에서 고친 내용이 아산초 자료에 바로 반영됨. 무료 한도도 함께 씀 | 관리자 계정·원본 등록을 새로 해야 함 |

다른 학교에서 쓰거나 연습용으로 쓰려면 **B**를 고르세요.

## 공통 준비

- Node.js 20 이상, Git
- B를 고르면 firebase-tools도 필요합니다: `npm i -g firebase-tools` 후 `firebase login`

```bash
git clone https://github.com/limhs06082-eng/2026asan-cur-meeting.git
```

```bash
cd 2026asan-cur-meeting && npm ci
```

## A. 같은 자료를 다른 주소로

1. `npm run build` → `dist/` 폴더가 생깁니다.
2. `dist/` 안의 파일을 웹 서버의 공개 폴더에 그대로 올립니다. 화면 이동은 주소의 `#` 뒤(예: `#board`)로 하므로 서버 경로 설정은 필요 없습니다.
3. 선생님들은 로그인 없이(익명) 바로 쓸 수 있습니다.
4. **관리자 Google 로그인**은 Firebase가 허용한 도메인에서만 됩니다. 새 주소에서 관리자 로그인이 필요하면 아산초 관리자에게 그 도메인을 Firebase 콘솔 → Authentication → 설정 → 승인된 도메인에 추가해 달라고 요청하세요. 관리자 작업은 기존 주소(https://asan-curriculum-link-2026.web.app)에서 해도 됩니다.

## B. 새 Firebase 프로젝트로 따로 운영

### 1) Firebase 콘솔에서 (https://console.firebase.google.com)

1. 프로젝트 만들기 (예: `myschool-curriculum-link`). Spark(무료) 요금제로 충분합니다. 다만 많은 인원이 하루 종일 쓰면 무료 한도를 넘을 수 있습니다(README 8장).
2. 웹 앱 추가(`</>`) → 나오는 설정값 중 `apiKey`, `authDomain`, `projectId`, `appId`를 적어 둡니다.
3. Authentication → 시작하기 → 로그인 방법에서 **익명**과 **Google**을 켭니다.
4. Firestore Database → 데이터베이스 만들기 → 위치 `asia-northeast3 (서울)`, 프로덕션 모드.
5. 다른 서버에 올릴 경우: Authentication → 설정 → 승인된 도메인에 그 서버 도메인을 추가합니다(관리자 Google 로그인용).

### 2) 파일 고치기 (5곳)

| 파일 | 바꿀 내용 |
| --- | --- |
| `.env.production` | 위 2)의 값 4개로 바꿉니다 (`VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`) |
| `.firebaserc` | `"default"` 값을 새 프로젝트 ID로 |
| `firestore.rules` | 11번째 줄 `bootstrapEmail()`의 이메일을 **새 관리자 Gmail**로 |
| `src/App.tsx` | 24번째 줄 `BOOTSTRAP_EMAIL`을 같은 Gmail로 |
| `firebase.json` | `supportEmail`을 같은 Gmail로 |

Vercel에 올린다면 `vercel.json`의 `asan-curriculum-link-2026.firebaseapp.com` 두 곳도 `새프로젝트ID.firebaseapp.com`으로 바꿉니다.

`firestore.rules`의 이메일과 `src/App.tsx`의 이메일이 같아야 합니다. 규칙에 적힌 계정만 최초 관리자가 될 수 있습니다(처음 들어온 사람이 관리자가 되는 방식이 아님).

### 3) 보안 규칙 배포와 화면 빌드

```bash
firebase deploy --only firestore --project 새프로젝트ID
```

```bash
npm run build
```

- `dist/`를 원하는 웹 서버에 올립니다. Firebase Hosting을 쓰려면 `firebase deploy --only hosting --project 새프로젝트ID`를 실행하면 `https://새프로젝트ID.web.app`이 생깁니다.
- 보안 규칙(`firestore.rules`)은 반드시 배포해야 합니다. 화면만 올리고 규칙을 배포하지 않으면 저장이 모두 거부됩니다.

### 4) 처음 쓰는 날

1. 올린 주소 첫 화면 아래 **‘Google 계정으로 관리자 로그인’** → 2)에서 적은 Gmail로 로그인 → **‘최초 관리자로 등록’**.
2. 관리 → 작업본·백업 → **‘등록할 카드 미리보기’** → **‘이 내용으로 2026 확인본 등록’** → **‘편집 열기’**.
3. 선생님들은 로그인 없이 주소에 들어와 이름·역할·학년을 고르고 씁니다.

### 우리 학교 활동으로 바꾸려면

기본 카드 120개는 아산초 2026 「교육활동 한눈에 보기」를 옮긴 것입니다(`src/seed/source-2026.json`). 다른 학교라면

- 이 파일을 그 학교 활동으로 바꾼 뒤 빌드하거나,
- 일단 등록한 뒤 화면에서 카드를 고치고 추가·제외해도 됩니다.

검토 주제와 영역 이름은 관리 화면에서 바꿀 수 있습니다.

## 알아 둘 점

- `.env.production`의 값은 공개되어도 되는 웹 식별값입니다. 접근 제어는 Firestore 보안 규칙이 합니다. 서비스 계정 키·Admin SDK 키는 이 저장소에 없고, 필요하지도 않습니다.
- 주소를 아는 사람은 로그인 없이 편집할 수 있게 만든 앱입니다. 주소를 학교 밖에 공유하지 마세요.
- 개발·테스트 방법은 README 3장을 보세요.
