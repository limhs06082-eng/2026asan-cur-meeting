## 화면 전수 점검 (헤드리스 Chrome, `scripts/browser-checks/`)

- 관리자·교사 계정 각각 4개 작업본(확정본·편집 중·성능 시험·준비 중) × 8개 화면 + 카드 상세·이력·연결 상세·출력 스냅샷: 콘솔 오류·경고 0건(SDK 12.19).
- 이 점검에서 실제 결함 2건을 찾아 고쳤습니다: ① 원문 출처에 빠진 값이 있는 카드에서 정렬 오류(공통 카드 나누기가 서버가 아닌 화면 객체를 복사하던 문제 포함), ② 접근할 수 없는 ‘준비 중’ 작업본을 먼저 구독했다가 바꿀 때의 SDK 내부 오류(목록에서 확인된 작업본만 구독하도록 수정).
- 사용 중 접근 회수 → 즉시 ‘접근 회수’ 화면, 복구 → 즉시 보드로 돌아옴, 오류 0건.

## 성능 (PRD 15장 끝)

에뮬레이터, 카드 200·연결 300 합성 작업본(`perf-test-200`, 개발 모드 빌드):
- 검색 입력 반영 33ms, 주제 필터 22ms, 카드 사이 선택 전환 약 40ms, 상세 패널 처음 열기 약 1초(개발 모드 — 운영 빌드는 더 빠를 것으로 예상, 미측정)
- 전체 연결선은 그리지 않고 선택한 카드(또는 켠 주제)의 연결만 그림

두 기기 간 3초 이내 반영 목표는 에뮬레이터의 같은 PC 두 탭에서 1초 이내로 보였으나, 학교 네트워크·실제 프로젝트에서의 측정은 미실시입니다.

## 읽기 사용량 (2026-11-02)

- 에뮬레이터, 롱폴링 응답의 `documentChange` 수로 측정(`?devLongPoll`, 개발 모드 전용): 교사 첫 접속 158건(2027 개편안 작업본), 다른 교사로 새로 접속 158건.
- 교사 계정 로그아웃을 ‘페이지 새로 불러오기’에서 ‘화면만 내리고 같은 탭 메모리 캐시 유지(LRU)’로 바꿈. 같은 창에서 다음 교사가 로그인하면 10개 구독 모두 재개 토큰(resumeToken)을 붙여 다시 연결하는 것을 확인. 에뮬레이터는 재개 토큰을 무시하고 전체를 다시 보내므로 절감량은 에뮬레이터에서 측정할 수 없음 — 실제 Firestore는 30분 이내 재개 시 바뀐 문서만 과금(공식 요금 안내). 실제 절감은 리허설 때 콘솔 사용량 탭으로 확인 필요.
- 교사1 → 같은 창 교사2(역할·담당 학년 표시 정확), 작업본 3개를 3바퀴 전환, 관리자 로그아웃은 새로고침 유지: 콘솔 오류·경고 0건. 화면 전수 점검 다시 실행 0건, 단위 테스트 24/24.
