# 아산초 교육과정 연결 협의 웹앱

선생님들이 2026 학년별 교육활동을 직접 확인하고, 1~6학년 사이의 배움 연결과 독립 운영 이유를 함께 기록·합의하여 2027 교육활동 한눈에 보기를 만드는 실시간 공동 작업 웹앱입니다. PRD: `../2026-11-01-교육과정연결웹앱-PRD.md`

- 운영 주소: **https://asan-curriculum-link-2026.web.app**
- Firebase 프로젝트: `asan-curriculum-link-2026` (Spark 무료 요금제, 결제 미설정, Firestore 위치 `asia-northeast3` 서울)
- 기술: React 18 + TypeScript + Vite 5, Firebase JS SDK 12.19 (Authentication·Cloud Firestore·Hosting)

## 1. 처음 쓰는 날 (관리자 준비 순서)

1. 운영 주소에 **limhs06082@gmail.com** 계정으로 Google 로그인합니다.
2. ‘승인 대기 중’ 화면의 **‘최초 관리자로 등록’**을 누릅니다. (보안 규칙 `firestore.rules`의 `bootstrapEmail()`에 지정된 계정만 성공합니다. 첫 방문자가 관리자가 되는 방식이 아닙니다.)
3. ‘관리 → 작업본·백업’에서 **‘등록할 카드 미리보기’**로 원본 seed 120개를 확인한 뒤 **‘이 내용으로 2026 확인본 등록’**을 누릅니다. 등록 직후 작업본은 ‘준비 중’이며 검사 결과(작업 seed: done)를 확인합니다.
4. **‘편집 열기’**를 누르면 선생님들이 편집할 수 있습니다.
5. 선생님들은 운영 주소에서 로그인 후 ‘접근 요청 보내기’를 누릅니다. 관리자는 ‘관리 → 구성원·권한’에서 요청마다 **역할(관리자·기획팀·열람자)**과 **학년도별 담당(학년 편집자·학년 대표)**을 정해 승인합니다. 승인 즉시 선생님 화면이 바뀝니다.
   - 같은 학교 메일이라도 자동 승인하지 않습니다. 링크를 받은 사람도 승인 전에는 아무 자료도 볼 수 없습니다.
   - 노트북 한 대를 여러 선생님이 함께 쓰면 그 노트북에 로그인한 계정 이름으로 이력이 남습니다. 학년 대표 확인은 학년 대표 계정으로 해야 합니다.
   - 공용 노트북은 사용 후 반드시 ‘로그아웃’하세요(로그인 상태가 브라우저에 유지됩니다). 다음 선생님은 창을 닫지 말고 같은 창에서 로그인하면 읽기 사용량이 줄어듭니다.

> 최초 관리자 계정을 바꾸려면 `firestore.rules`의 `bootstrapEmail()`과 `src/App.tsx`의 `BOOTSTRAP_EMAIL`을 고친 뒤 다시 배포합니다.

## 5. 데이터 구조

```text
workspaces/asan
  members/{uid}            역할·학년도별 담당(scopes.y2026 = {edit:[..], lead:[..]})·활성
  accessRequests/{uid}     승인 요청(본인만 작성)
  sources/{sourceId}       원본 PDF 이름·SHA-256·쪽수·seed 버전
  jobs/{jobId}             원본 등록·복제 작업 진행·검사 결과
  years/{yearId}           작업본(2026-review-v1, 2027-plan-v1 …): 상태(준비 중/편집 중/확정본)·영역·주제
    cards/{cardId}         카드(내용 버전 contentVersion, 제외는 deletedAt)
    connections/{id}       연결. ID = 종류__시작카드__도착카드(대칭은 정렬) → 같은 연결 중복 불가
    approvals/{id}         연결의 학년 대표 확인(연결 버전·양 끝 카드 버전 기록)
    cardChecks/{cardId}    카드별 학년 사실 확인(내용 버전 기록)
    reviews/{cardId__주제} 독립 운영·추가 확인 판단과 대표 확인
    gradeReviews/g{n}      학년 정비 완료(그 시점 카드 버전 목록)
    proposals/{id}         제안(논의 중/수용/보류/반려, 다음 학년도 전달)
    discussions/{id}       의견(작성만 가능)
    dupDecisions/{pair}    중복 후보를 ‘별도 활동’으로 확인한 기록
    events/{operationId}   변경 이력(생성만 가능, 행위자·서버 시각 검증)
```

- 확인·합의는 저장된 플래그가 아니라 **현재 카드·연결 버전과 확인 기록의 버전이 일치하는지**로 화면에서 계산합니다. 카드나 연결 내용이 바뀌면 이전 확인은 자동으로 ‘재확인 필요’가 됩니다.
- 모든 공동 데이터 변경은 트랜잭션으로 저장하며, 같은 트랜잭션에 이력(event)을 함께 씁니다. 규칙은 `getAfter`로 둘이 함께 저장되는지 검사합니다.
- 같은 사용자 작업은 같은 operationId를 재사용합니다. 시간 초과 후 다시 저장해도 이력이 이미 있으면 ‘앞선 시도에서 저장됨’으로 처리해 이중 등록이 생기지 않습니다.

## 6. 원본 seed 등록·재실행·검증

- seed 파일: `src/seed/source-2026.json` (원본 1쪽 표를 사람이 옮긴 초안, 120개 활동). 원본 PDF SHA-256: `52f6a7c4263ecb96c6e335ff014ff742f66d57b46594a2f43f1fd28bc86256b2`.
- 배움·자람·나눔은 원본 아이콘을 확대해 판독한 값입니다(아이콘 없는 행은 빈 값). 학년 확인이 필요합니다.
- 공통 교육과정·기타의 병합 셀 활동 13개는 ‘학교 공통’ 카드로만 등록하고 ‘적용 학년 확인 필요’를 붙였습니다. 생존수영 등을 전 학년에 일괄 등록하지 않습니다. 확인 후 상세 패널의 ‘학년별 카드로 나누기’를 씁니다.
- 한 칸에 여러 활동이 있는 경우(예: 5학년 ‘PPT 활용한 발표, SW/AI교육’)는 한 카드로 두고 ‘별도 활동인지 묶음인지 확인’ 메모를 붙였습니다.
- 1·2학년 ‘학교자율시간’ 행은 원본 행 이름을 보존하고 ‘실제 편성 영역 확인 필요’를 붙였습니다.
- 카드 ID가 원본 위치로 정해져(`s26-g{학년}-{영역}-{순번}`) 같은 seed를 다시 실행해도 카드가 늘어나지 않습니다(에뮬레이터에서 재실행 후 120개 유지 확인). 이미 있는 카드는 덮어쓰지 않고 건너뜁니다.
- 참고 분석 자료(`2026-11-01-교육과정연결검토/`)의 추천·위계는 **등록하지 않았습니다**(합의된 결과가 아니므로).

## 7. 백업·복구

- 관리 → 작업본별 **‘JSON 백업’**: schemaVersion, 원본 정보, 작업본, 카드·연결·확인·판단·제안·의견·이력 포함. 이메일·구성원 권한은 들어가지 않습니다(이력의 uid는 포함 — 관리자 보관용).
- **‘백업 가져오기’**: 구문·버전·참조 관계를 검사한 뒤 **새 작업본(준비 중)**으로 가져옵니다. 기존 작업본에 덮어쓰지 않으며 같은 ID면 거부합니다. 기록 시각은 원래 값으로 보존합니다. 검사 후 ‘편집 열기’.
- 잘못된 카드 수정은 카드 상세 → 변경 이력 → ‘이 변경 이전 값으로 되돌리기’(새 변경으로 저장), 제외한 카드는 ‘복원’(새 버전, 옛 확인은 되살아나지 않음).
- 확정본은 고칠 수 없습니다. 정정은 ‘정정용 새 수정본’(예: `2026-review-v2`)을 만들어 합니다.
- 회의 전후로 JSON 백업을 내려받아 학교 드라이브에 보관하기를 권합니다.

## 8. 비용·사용량 (꼭 읽어 주세요)

현재 프로젝트는 **Spark(무료) 요금제**이며 결제 계정을 연결하지 않았습니다. 무료 한도를 넘으면 요금이 나가는 대신 **다음 초기화(미국 태평양 시각 자정 = 한국 오후 5시, 3~11월 미국 서머타임 기간에는 오후 4시)까지 읽기·쓰기가 거부**됩니다. 전날 오후 5시 이후의 리허설·등록 작업도 다음 날 회의와 같은 한도에 들어갑니다. 특정 비용·무료 사용을 보장하지 않습니다. [공식 요금 안내](https://firebase.google.com/docs/firestore/pricing)

| 항목 | Spark 일일 한도 | 이 앱의 예상 |
| --- | --- | --- |
| 문서 읽기 | 50,000 | 접속 1회(새로고침 포함)마다 현재 작업본 전체 ≈ 카드 120 + 연결·확인 기록 수(초기 약 250~600건). 다른 사람의 변경 1건마다 접속 중인 화면 수만큼 추가 |
| 문서 쓰기 | 20,000 | 저장 1회 = 2~4건(내용 + 이력) |

- 예: 노트북 14대가 각각 하루 10번 새로 접속(작업본 문서 600개 기준) → 약 84,000 읽기로 **무료 한도를 넘을 수 있습니다**. 같은 화면을 띄워 둔 채 쓰면(새로고침하지 않으면) 처음 한 번만 전체를 읽고 이후에는 바뀐 것만 읽습니다.
- 노트북을 돌려 쓸 때 교사 계정은 ‘로그아웃’ 후 같은 창에서 다음 선생님이 로그인하면, 이미 받은 작업본 문서를 메모리에 남겨 두었다가 30분 안이면 바뀐 문서만 서버에서 받습니다(창을 닫거나 새로고침하면 전체를 다시 읽음). 관리자 계정의 로그아웃은 구성원 명단까지 비우기 위해 페이지를 새로 불러옵니다.
- 예상(노트북 8대·2시간, 작업본 문서 약 500개까지 늘어나는 경우): 새로 접속 노트북당 3번이면 약 1.6만, 8번이면 약 3.5만, 계정 교체마다 새로 접속해 20번이면 약 7.7만 읽기. 같은 창 로그아웃·로그인을 쓰면 계정 교체 비용이 거의 사라집니다.
- 30분 넘게 연결이 끊겼다가 다시 연결되면 전체를 다시 읽을 수 있습니다. 보안 규칙의 문서 조회(get)도 별도 읽기로 계산됩니다.
- 전 교직원 다모임(약 50명·14대)처럼 많이 쓰는 날을 앞두고는 **Blaze(종량제) 전환 + 예산 알림(예: 월 1,000원)** 설정을 권합니다. 이 규모의 예상 비용은 하루 수십 원 수준이지만, 결제 설정은 운영자가 직접 판단·설정해야 하며 이 작업에서는 바꾸지 않았습니다.
- 사용량 확인: Firebase 콘솔 → Firestore → 사용량 탭.

## 9. 오프라인·저장 표시
